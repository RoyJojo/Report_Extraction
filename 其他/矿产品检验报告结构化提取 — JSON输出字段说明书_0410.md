# 矿产品检验报告结构化提取 — JSON输出字段说明书

> **版本**: v1.0 | **日期**: 2026年4月10日 | **适用对象**: 业务人员、产品经理、开发人员、新员工

---

## 1. 业务背景

### 1.1 矿产品贸易简介

矿产品国际贸易是一个涉及矿山开采、贸易商、冶炼厂、船运公司、第三方检验机构和海关等多方参与的复杂业务。一笔典型的贸易流程大致如下：

**卖方（矿山/贸易商）** 将矿产品从装货港装船，运往 **买方（冶炼厂/贸易商）** 指定的卸货港。货物到港后，需要由第三方检验机构对货物的 **重量** 和 **品质** 进行检验，以确定最终的结算价格。

在这个过程中，会产生大量的检验报告、化验证书、品质证书等文档。这些文档是贸易结算的核心依据，其中的数据需要被准确提取并录入业务系统。

### 1.2 主要商品类型

本系统目前覆盖的主要矿产品类型包括：

**铜精矿（Copper Concentrates）**：由铜矿石经选矿后得到的精矿粉末，铜含量通常在20%-30%。贸易中的计价元素主要是铜（Cu）、金（Au）、银（Ag），同时需关注砷（As）、氟（F）等杂质元素，因为超标会被罚款。

**铁矿石（Iron Ore）**：分为块矿（Lump）和粉矿（Fines）。计价元素为全铁（TFe），杂质元素包括二氧化硅（SiO₂）、三氧化二铝（Al₂O₃）、硫（S）、磷（P）等。粒度分布也是重要的品质指标。

**镍铁/镍生铁（Ferro Nickel / Nickel Pig Iron）**：含镍铁合金，计价元素为镍（Ni），杂质元素包括硅（Si）、碳（C）、硫（S）、磷（P）、铬（Cr）等。镍铁通常指印尼/新喀产铸锭，镍生铁通常指中国/印尼产的低品位含镍铁合金。

### 1.3 检验报告的类型

在一笔贸易中，通常会产生以下几类检验报告：

| 报告类型 | 说明 |
|---------|------|
| **CIQ品质证书/重量证书** | 中国海关出入境检验检疫机构出具，是进口货物通关的必要文件。品质证书包含化学成分检测结果，重量证书包含水尺计重或称重结果。 |
| **第三方综合检验报告** | 由独立的国际检验机构（如 Intertek、SGS、Bureau Veritas、CCIC 等）出具。可能同时包含重量和品质数据。 |
| **第三方品质证书** | 仅含品质/化验数据的第三方证书。 |
| **卖方化验报告** | 由矿山或生产商自行化验后出具，如 PT Freeport 的 Assay Submittal。 |
| **买方化验报告** | 由买方或其委托的冶炼厂化验后出具。 |
| **仲裁化验报告** | 当买卖双方的化验结果存在差异且超过合同约定的允许范围时，由双方共同选定的独立实验室进行仲裁检测，其结果作为最终结算依据。 |
| **品质交换意见书** | 买卖双方交换各自的化验结果，用于比对和协商。 |
| **贸易商证书** | 由贸易商（如 Trafigura、Glencore）出具的品质证书。 |

### 1.4 核心业务概念

#### Lot（批次）

一船货物通常会被分成多个 Lot（批次）进行取样和化验。每个 Lot 是一个独立的计价单元，有自己的重量和化验结果。例如一船 5000 吨的铜精矿可能被分成 22 个 Lot，每个 Lot 约 200-500 吨。

#### Sub-lot（子批次）

部分报告中，一个 Lot 下还会细分为多个 Sub-lot。典型场景是镍铁检验报告：一个大批次 P1 下可能有 7 个子批次 P1-1 到 P1-7，每个子批次有独立的镍含量检测结果，然后加权平均得到 P1 整体的镍含量。

#### Composite（混合样）

某些元素（特别是杂质元素）不会逐 Lot 检测，而是将所有 Lot 的样品混合后统一检测，这就是 Composite（混合样）。例如铜精矿中的砷（As）含量通常只报告一个全船的 Composite 值。Composite 可以是全船一个，也可以每个 Lot 各一个。

#### 计价元素与杂质元素

**计价元素（Payable Elements）** 是买方需要为之付款的有价元素，如铜精矿中的铜、金、银。这些元素会逐 Lot 检测，因为它们直接影响每个 Lot 的结算金额。

**杂质元素（Penalty Elements）** 是超过合同约定限值时会被罚款的有害元素，如铜精矿中的砷（As）、氟（F）等。这些元素通常只在 Composite 级别检测。

#### DMT 与 WMT

**DMT（Dry Metric Ton，干吨）**：去除所有水分后的货物重量，是贸易结算的基础。

**WMT（Wet Metric Ton，湿吨）**：含水分的货物重量。WMT × (1 - 水分%) = DMT。

### 1.5 本功能的作用

本功能使用 AI 视觉大模型自动读取上述各类检验报告（PDF文件），将其中的关键信息提取为统一的 JSON 格式结构化数据。提取结果可直接导入业务系统，替代人工录入，大幅提高效率并减少错误。

下文将逐一解释提取结果中每个 JSON 字段的含义。

## 2. JSON 整体结构概览

提取结果的 JSON 分为以下 7 个一级模块：

| 模块 | 类型 | 说明 |
|------|------|------|
| `report` | 对象 | 报告元信息：报告编号、类型、出具机构、签发日期、检验标准等 |
| `trade` | 对象 | 贸易信息：买卖双方、合同号、船名、装卸港、日期等 |
| `cargo` | 对象 | 货物信息：商品类型、名称、品质/品牌、申报数量、包装方式 |
| `inspection_data` | 对象 | **核心数据**：全船重量汇总和元素含量（overall），以及逐批次的重量和化验结果（lot_data） |
| `physical_properties` | 对象 | 物理指标：粒度分布等 |
| `seals` | 对象 | 封签信息：封签机构、类型、状态 |
| `extraction_confidence` | 对象 | 提取置信度：整体可信度、不确定的字段列表 |
| `notes` | 字符串 | 备注信息：重要的补充说明、异常情况等 |

## 3. report — 报告元信息

记录报告本身的基本信息，用于识别和分类。

| 字段 | 类型 | 含义 |
|------|------|------|
| `report_id` | 字符串 | 报告的主要编号。不同机构编号风格不同，如 Intertek 用 `MIN260100148NC`，北矿用 `K22-070096`。如报告上有多个编号，取最主要的一个。 |
| `report_number` | 字符串 | 报告流水号。部分机构会在 report_id 之外另给一个流水号，如 Intertek 的 `RMIN2600595`。无则为 null。 |
| `report_date` | 日期 | 报告签发日期，格式为 `YYYY-MM-DD`。 |
| `report_type` | 枚举 | 报告类型。可选值见下方说明。 |
| `issuing_organization` | 字符串 | 出具机构全称。如 `Intertek Testing Services Ltd., Shanghai`。 |
| `issuing_organization_short` | 字符串 | 出具机构简称。如 `Intertek`、`CCIC`、`SGS`、`BV`、`AHK`、`BGRIMM` 等。 |
| `inspection_standard` | 数组 | 检验中使用的标准列表。如 `["GB/T 6730.65-2009", "ISO 3087:2020"]`。 |
| `analysis_methods` | 对象 | 各元素对应的分析方法。如 `{"Cu": "W0700 - Volumetric"}`。报告中未标注方法时为空对象。 |

### report_type 可选值

| 值 | 含义 |
|----|------|
| `ciq_quality` | CIQ品质证书 |
| `ciq_weight` | CIQ重量证书 |
| `third_party_inspection` | 第三方综合检验报告（同时含重量和品质） |
| `third_party_quality` | 第三方品质/化验证书（仅含品质） |
| `third_party_weight` | 第三方重量证书（仅含重量） |
| `seller_assay` | 卖方化验报告 |
| `buyer_assay` | 买方化验报告 |
| `assay_exchange` | 品质交换意见书 |
| `umpire_assay` | 仲裁化验报告 |
| `trader_certificate` | 贸易商出具的品质证书 |
| `other` | 无法归入以上类别 |

## 4. trade — 贸易信息

记录这笔贸易的买卖双方、合同、船运等信息。不同类型的报告包含的贸易字段不同，缺失的字段为 null。

| 字段 | 类型 | 含义 |
|------|------|------|
| `buyer` | 字符串 | 买方/收货人/委托方名称。 |
| `seller` | 字符串 | 卖方/发货人名称。部分报告不包含卖方信息。 |
| `contract_no` | 字符串 | 合同编号。 |
| `invoice_no` | 字符串 | 发票号。 |
| `bl_no` | 字符串 | 提单号（Bill of Lading Number）。提单是船运公司签发的货物运输凭证。 |
| `client_ref` | 字符串 | 客户参考号，检验机构按客户的编号体系标注的参考号。 |
| `vessel` | 字符串 | 运输船舶的名称。 |
| `voyage_no` | 字符串 | 航次编号。 |
| `loadport` | 字符串 | 装货港（发货地）。 |
| `discharge_port` | 字符串 | 卸货港（收货地）。 |
| `arrival_date` | 日期 | 货物到港日期，格式 `YYYY-MM-DD`。 |
| `completion_of_discharge_date` | 日期 | 卸货完成日期。 |
| `inspection_date` | 字符串 | 检验日期范围，如 `2026-01-16 to 2026-01-18`。 |
| `sampling_dates` | 字符串 | 取样日期范围。 |

> **注意**：仲裁报告通常不含船名、装卸港等信息，卖方报告可能不含买方名称，这些都是正常的。

## 5. cargo — 货物信息

描述货物本身的基本属性。

| 字段 | 类型 | 含义 |
|------|------|------|
| `commodity` | 枚举 | 商品大类。可选值：`iron_ore_lump`（铁矿块矿）、`iron_ore_fines`（铁矿粉矿）、`iron_ore_pellet`（铁矿球团）、`copper_concentrates`（铜精矿）、`ferro_nickel`（镍铁）、`nickel_pig_iron`（镍生铁）、`zinc_concentrates`（锌精矿）、`lead_concentrates`（铅精矿）、`other`（其他）。 |
| `commodity_name` | 字符串 | 商品名称原文，保留报告中的原始表述。如 `铁矿块 IRON ORE LUMP`、`ARANZAZU COPPER CONCENTRATES`。 |
| `quality_name` | 字符串 | 品质/品牌名称，即矿山或产品的特定名称。如 `Grasberg`、`Red Chris`、`SP10F`。无法识别时为 null。 |
| `declared_quantity` | 数字 | 申报数量（数值），即合同或提单上载明的货物数量。 |
| `declared_quantity_unit` | 字符串 | 申报数量的单位，如 `MT`（公吨）、`KG`、`DMT`（干吨）。 |
| `packing` | 字符串 | 包装方式。常见值：`In bulk`（散装）、`In bags`（袋装）。 |

## 6. inspection_data — 检验数据（核心）

这是整个 JSON 中最重要的部分，包含全船的重量和元素汇总数据（overall），以及逐批次的重量和化验结果（lot_data）。

### 6.1 顶层字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `analysis_state` | 枚举 | 化验状态。`dry_basis` 表示干基（去除水分后计算），`as_received` 表示原样基础。绝大多数报告为 `dry_basis`。 |
| `weighing_method` | 字符串 | 称重方式。常见值：`draft survey`（水尺计重，通过测量船舶吃水深度推算货重）、`bridge scale`（地磅/汽车衡，逐车过磅）、`belt scale`（皮带秤）、`hopper scale`（料斗秤）。无称重数据时为 null。 |
| `scale_details` | 字符串 | 地磅/衡器信息，包括型号和有效期。如 `SCS-120, expiry 2026-07-08`。无则为 null。 |

### 6.2 overall — 全船汇总数据

记录整船货物的总体重量和全船级元素含量。**overall 对象始终存在**（不为 null），其中各字段独立判断是否有值。

#### 重量字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `bl_weight_mt` | 数字 | 提单重量（MT）。提单上记载的货物重量，通常为装港的湿重。 |
| `total_gross_weight_mt` | 数字 | 总毛重（MT）。毛重 = 载具满载过磅的总质量，包含载具自重（皮重）、货物、水分和杂质。仅出现在地磅称重场景中。 |
| `total_tare_weight_mt` | 数字 | 总皮重（MT）。皮重 = 空载具（卡车/容器）过磅的质量，即载具自身重量。 |
| `total_impurities_weight_mt` | 数字 | 总杂质重量（MT）。货物中混入的非目标物质（泥土、石块、铁丝等异物）。主要出现在镍铁/镍生铁的 Inspection Report 中。 |
| `total_moisture_weight_mt` | 数字 | 总运输水分扣减量（MT）。运输过程中附着在货物表面的水分质量，需在称重时扣除。注意：这是称重环节扣除的水分重量（绝对值MT），与化验环节测定的水分百分比不同。 |
| `total_wet_weight_mt` | 数字 | 总湿重（MT）。湿重 = 毛重 - 皮重，即含水分和杂质的货物总重。水尺计重通常直接给出此值。 |
| `total_dry_weight_mt` | 数字 | **总干重/净干重（MT）**。去除所有水分后的货物质量。**这是贸易结算最核心的重量数据。** |
| `moisture_at_discharge_pct` | 数字 | 卸货时整体水分百分比（%）。用于从湿重推算干重。 |
| `moisture_deduction_mt` | 数字 | 总水分扣减量（MT）。= 湿重 × 水分百分比。 |

#### 元素字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `elements` | 对象或 null | 全船级元素汇总数据。来源有两种：(1) 全船混合样（Composite）的杂质检测结果；(2) 报告中明确给出的全船加权平均值。无全船级元素数据时为 null。详见下方元素对象说明。 |

### 6.3 lot_data — 逐批次数据

数组，每个元素代表一个 Lot（批次）。将该 Lot 的重量数据和化验数据合并在同一个结构中。

#### 重量字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `lot_id` | 字符串 | 批次编号，保留报告原始编号。如 `1`、`P1`、`lot1` 等。 |
| `gross_weight_mt` | 数字 | 该批次毛重（MT）。来自报告称重章节。无称重章节时为 null。 |
| `tare_weight_mt` | 数字 | 该批次皮重（MT）。来自报告称重章节。 |
| `impurities_mt` | 数字 | 该批次杂质重量（MT）。 |
| `moisture_mt` | 数字 | 该批次水分扣减量（MT）。 |
| `wet_weight_mt` | 数字 | 该批次湿重（MT）。 |
| `dry_weight_mt` | 数字 | **该批次干重/净干重（MT）**。这是该批次参与贸易结算的核心重量。可能来自称重章节的"Net weight of cargo"，也可能来自化验表的 DMT 列。 |
| `moisture_pct` | 数字 | 该批次的水分百分比。 |

> **重量字段来源说明**：
> - 来自**称重/过磅章节**（如 Inspection Report 中的 WEIGHING 部分）：此时 gross_weight_mt、tare_weight_mt、impurities_mt、moisture_mt 通常都有值。
> - 来自**化验表**（如铜精矿化验证书中的 DMT 列）：此时通常只有 dry_weight_mt（和/或 wet_weight_mt、moisture_pct），其余称重字段为 null。

#### 化验字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `elements` | 对象 | 该 Lot 所有已知元素的化验结果。包括计价元素的逐Lot检测结果，以及 per-lot composite 杂质数据（如有）。**未检测的元素不会出现在该对象中。** 详见下方元素对象说明。 |
| `sub_lots` | 数组 | 子批次列表。仅在报告中存在子批次结构时填充，否则为空数组 `[]`。每个子批次包含 `sub_lot_id`（子批次编号）和 `elements`（化验结果）。 |

### 6.4 元素对象说明

无论出现在 `overall.elements`、`lot_data[].elements` 还是 `sub_lots[].elements` 中，每个元素的结构相同：

```json
{
  "Cu": {
    "value": 21.22,
    "unit": "%",
    "category": "payable"
  }
}
```

| 字段 | 类型 | 含义 |
|------|------|------|
| `value` | 数字 | 元素含量的数值，保持原始精度。 |
| `unit` | 字符串 | 含量单位。常见值：`%`（百分比）、`g/t`（克/吨）、`ppm`（百万分之一）。 |
| `category` | 枚举 | 元素分类。`payable` = 计价元素（买方付款的有价元素），`penalty` = 杂质/罚款元素（超标会被罚款的有害元素）。 |

**常见元素分类速查**：

| category | 铜精矿 | 铁矿 | 镍铁/镍生铁 |
|----------|--------|------|------------|
| **payable** | Cu, Au, Ag | Fe (TFe) | Ni |
| **penalty** | As, Cd, Zn+Pb, Bi, Sb, Hg, F, Al₂O₃+MgO | SiO₂, Al₂O₃, S, P | Si, C, S, P, Cr |

**关于稀疏数据**：部分报告中并非每个 Lot 都报告了所有元素。例如仲裁报告可能仅对部分 Lot 检测了铜含量。在这种情况下，未检测的元素不会出现在该 Lot 的 elements 中——**不是值为 null，而是整个键值对都不存在。** 具体的稀疏情况会在 `notes` 中说明。

## 7. physical_properties — 物理指标

记录货物的物理特性，目前主要是粒度分布。粒度分布主要与铁矿石相关。

| 字段 | 类型 | 含义 |
|------|------|------|
| `size_distribution` | 数组 | 粒度分布数据。每个元素包含以下字段：|

**size_distribution 元素字段**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `fraction` | 字符串 | 粒度描述。如 `-6.3mm`（小于6.3mm）、`+40mm`（大于40mm）、`>6.3mm`。 |
| `value` | 数字 | 该粒度范围的占比数值。 |
| `unit` | 字符串 | 单位，通常为 `%`。 |
| `standard` | 字符串 | 检测标准。如 `ISO 4701:2019`。 |

> **注意**：铜精矿和镍铁报告通常没有粒度数据，此时为空数组 `[]`。

## 8. seals — 封签信息

记录样品的封签状态。封签是贸易中确保样品未被篡改的重要措施。取样后，样品会被多方共同封签，化验前检查封签是否完好。

| 字段 | 类型 | 含义 |
|------|------|------|
| `seal_details` | 数组 | 封签明细列表。无封签信息时为空数组 `[]`。 |

**seal_details 元素字段**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `organization` | 字符串 | 封签机构名称。 |
| `seal_type` | 字符串 | 封签类型。如 `Company Sealing Tape`（公司封条）、`Company Stamp`（公司印章）。 |
| `status` | 字符串 | 封签状态。`intact` 表示完好，`broken` 表示破损。 |

## 9. extraction_confidence — 提取置信度

AI 模型对提取结果的自评估。由于部分报告为扫描件，可能存在 OCR 识别困难，该字段帮助业务人员判断哪些数据需要人工复核。

| 字段 | 类型 | 含义 |
|------|------|------|
| `overall` | 枚举 | 整体置信度。`high` = 所有数值清晰可读；`medium` = 大部分清晰但有1-3处不确定；`low` = 多处模糊或布局难以解析。 |
| `uncertain_fields` | 数组 | 不确定的字段列表。空数组表示无不确定项。 |

**uncertain_fields 元素字段**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `field_path` | 字符串 | 该不确定字段在 JSON 中的路径。如 `inspection_data.lot_data[2].elements.Cu.value`。 |
| `original_text` | 字符串 | 报告中该处的原始文本（如能识别）。 |
| `reason` | 枚举 | 不确定原因。可选值：`ocr_unclear`（OCR不清晰）、`ambiguous_layout`（表格布局歧义）、`overlapping_text`（文字重叠）、`low_resolution`（低分辨率）、`conflicting_values`（数值矛盾）、`stamp_obstruction`（印章遮挡）。 |

> **使用建议**：当 `overall` 为 `medium` 或 `low` 时，建议业务人员重点核对 `uncertain_fields` 中列出的字段，对照原始报告PDF确认数值的准确性。

## 10. notes — 备注信息

自由文本字段，记录报告中的重要补充说明和异常情况。典型内容包括：

| 场景 | 示例 |
|------|------|
| **DMT来源说明** | `DMT values provided by client` — 表示干重数据由客户提供，而非本报告检测。 |
| **稀疏数据说明** | `Cu only reported for lots 1,2,11,12,13,15,18` — 表示铜含量仅对部分 Lot 检测。 |
| **单位原始标注** | `Original Au unit in report: g/1000kg` — 记录报告中金含量的原始单位（已统一转为 g/t）。 |
| **Lot编号异常** | `Lot numbering is non-sequential (lots 3,5,14 are missing)` — 表示报告中的批次编号不连续。 |
| **per-lot composite合并** | `Per-lot composite data (Composite P1/P2/P3) merged into each lot's elements` — 说明每个批次的杂质数据已合并到对应 lot 的 elements 中。 |
| **检验备注** | `Impurity result from random truck checking is referential only` — 杂质数据仅供参考。 |

## 11. 空值（null）说明

JSON 中大量字段可能为 null，这是正常情况，表示该信息在报告中不存在。常见原因：

**报告类型不包含该信息**：例如仲裁报告通常没有船名、装卸港等贸易信息；化验证书通常不包含毛重、皮重等过磅明细。

**化验报告无称重章节**：大多数化验证书只有 dry_weight_mt（来自化验表的DMT列），其余重量字段（gross_weight_mt、tare_weight_mt、impurities_mt等）为 null。

**全船无汇总数据**：部分报告（如仲裁报告）不提供全船加权平均值或全船composite数据，此时 `overall.elements` 为 null。

**元素缺失的处理方式不同**：与其他字段不同，如果某个 Lot 的某个元素未检测，该元素**不会出现在 elements 对象中**（而非值为 null）。这是为了区分"未检测"和"检测结果为0"。
